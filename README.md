# 今日のおやつひろば

Webコミュニティ（仮称）に入る前のライト層に向けて、診断・投票・ひとこと投稿・体験チェックインを通じておやつ商品との接点を作るLINEミニアプリ想定UIです。

> 提案・許諾前の確認用として、会社名・正式サービス名・実商品名は使用せず、すべて仮称と架空商品にしています。

## 体験コンセプト

- メイン: 今日の気分からおやつタイプを診断する
- サブ: みんなの投票とひとことで、軽いコミュニケーションを生む
- 体験記録: 施設や工場見学、ポップアップイベントのチェックインをカードとして残す
- 現地導線: 施設や工場見学、ポップアップイベントのLINEタッチからチェックインし、ハートと体験カードを受け取る
- 報酬: 診断、投票、ひとこと、体験ミッションでハートが貯まる
- 導線: 貯まったハートを使うためにWebコミュニティ（仮称）へ流入する

## 構成

- `index.html`: 画面の読み込み口、スマホ筐体風の外枠
- `styles.css`: 見た目、スマホ筐体、親しみやすい赤基調の配色、診断・投票・体験カード・体験ミッションUIの調整
- `src/config.js`: アプリ名、文言、ナビ、LIFF差し替え用の設定
- `src/data.js`: 商品、診断設問、診断結果、投票、体験カード、体験ミッション、ハート付与ルール、コミュニティ導線
- `src/app.js`: 画面切り替え、診断、投票、お菓子付きひとこと投稿、体験チェックイン、カード付与、ハート付与、端末内保存
- `assets/products/`: 診断結果・投稿用の差し替え可能な商品画像

## LINEミニアプリ化に向けた前提

- いまは通常ブラウザで確認できる静的UIです。
- LIFF SDKの読み込み、`liff.init()`、ログイン状態、プロフィール取得、バックエンドAPI連携は未接続です。
- 本番化では診断結果、投票、ひとこと、カード履歴、イベント参加履歴、ハート残高をサーバー側で保存する想定です。
- 体験チェックイン、カード付与、ハート付与の判定も、本番ではサーバー側で行います。
- Webコミュニティ（仮称）でハートを実際に利用するには、Webコミュニティ側の会員ID連携とハート台帳連携が必要です。
- 工場見学やイベントでは、LINEタッチの接点にイベントIDを付け、対象ミッションを出し分ける想定です。

## 確認観点

- 起動直後に診断画面が表示される

- 好きなお菓子を選んでひとことを送ると、お菓子名と一緒に一覧へ追加される
- 4つの体験ミッションを完了するとハートが増える
- チェックインした体験カードが保有カードへ追加される
- コミュニティ導線に現在のハート残高が表示される
- 360px幅程度でもボタンや文字がはみ出さない
